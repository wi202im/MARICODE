# Maricode 개선 방향 가이드

2026-11-04 작성. 최근 변경(2026-11-01~04 커밋 146개)을 바탕으로 정리한 **방향과 찾는 방법**이다. 현재 상태는 [handoff.md](handoff.md), 요구사항은 [goals.md](goals.md)를 따른다. 이 문서에는 상태를 적지 않는다.

## 1. 지금까지의 방향

한 줄 요약: **공식 CLI와 HAPI 위에 얇게 올린, VS Code 같은 AI 작업 공간.**

| 방향 | 근거가 된 변경 |
|---|---|
| 공식 CLI·HAPI에 맡긴다 | 앱 전용 프로필 → 기존 CLI 연결. 명령 카드 → `hapi resume` 터미널 이어가기. 대기 취소·지금 반영·사고 과정·파일 검색·중지는 HAPI에 이미 있던 기능을 연결 |
| 편집기급 작업 공간 | 파일 탭 뷰어·트리·diff 탭·변경 파일 카드·@파일, VS Code Dark Modern·Codicons·VSCode Elements |
| 선두 AI 채팅과 같은 조작감 | 중지·대기열, 진행 중 단계, 사고 과정, 요청 고정, 명령 팔레트·찾기 |
| 사고를 막는 안전장치 | 브랜치 고정, 접수 확인 전 재전송 금지, 이 Mac·등록 폴더 검사, 단기 미디어 링크 |
| 불필요한 단계 줄이기 | 보내면 자동 재개, 실행 환경이 꺼져 있어도 파일 목록, 도구 탭 제거 |

## 2. 원칙 (우선순위 순)

1. **실사용 확인 먼저, 배포 단위로 끊는다.** 새 기능보다 handoff의 `확인 안 함`을 줄인다. 확인된 것만 다음 배포 범위에 넣는다(배포는 사용자 지시로만).
2. **"HAPI에 이미 있나?"를 먼저 묻는다.** HAPI 경로·문서·소스(`.runtime/hapi-src`)를 확인한 뒤 설계한다. 2026-11-04에만 ‘불가’ 판단이 HAPI 확인으로 세 번 뒤집혔다.
3. **기준 제품은 VS Code(Copilot Chat)와 Claude Code·Codex 앱.** 화면과 기능 모두 이 기준과 비교해 차이를 정한다.
4. **화면 변경은 시안으로 먼저 고른다.** 합성 Hub 화면이나 실제 렌더링 시안을 보여 주고 고른 뒤 만든다. 만든 뒤 판단하면 되돌림이 생긴다(4일간 제거·되돌림 8건).
5. **손대는 곳부터 나눈다.** `app.mjs`(약 1,300줄, 4일간 63회 변경)는 기능을 고칠 때 그 부분만 모듈로 옮긴다. 한 번에 쪼개지 않는다.

## 3. 개선 포인트를 찾는 방법

| 방법 | 찾는 것 | 하는 법 |
|---|---|---|
| 검증 부채 | 만들었지만 확인 못 한 것 | `grep -n "확인 안 함" docs/handoff.md` → 실사용 체크리스트로 바꿔 하나씩 지운다 |
| HAPI 미사용 기능 | 이미 있는데 안 쓰는 기능 | HAPI Hub 경로(`.runtime/hapi-src/hub/src/web/routes/*.ts`의 `app.get/post/... ('/sessions/:id/...')`)와 앱 서버 `allowedRoute`·`server.mjs` 비교. 설정처럼 동적으로 쓰는 경로는 거른다. HAPI 릴리스 노트도 함께 본다 |
| 기준 제품 차이 | 사용자가 기대할 기능 | VS Code 월간 릴리스 노트, Claude Code·Codex 앱 문서로 "있음/부분/없음" 표를 만든다 |
| 수정이 몰리는 곳 | 깨지기 쉬운 영역 | `git log --since=<날짜> --name-only --format=` 파일별 변경 수, 같은 날 `feat` 뒤에 `fix`가 붙은 기능 |
| 실사용 신고 | 실제 불편 | handoff의 ‘실사용 신고’를 모아 반복 유형(실행 환경 꺼짐, 경로·환경 문제 등)을 찾는다 |
| 아직 못 본 화면 상태 | 승인 카드·경고·오류 화면 | 합성 Hub에 해당 상태를 넣어 렌더링하고 캡처해 검토한다 |

## 4. Claude가 직접 하는 검증 단계

아래로 갈수록 실제에 가깝고 사용자 확인이 필요하다. 결과는 handoff에 `된다/안 된다/확인 안 함`과 단계(L1~L4)를 함께 적는다.

| 단계 | 방법 | 확인할 수 있는 것 | 필요한 것 |
|---|---|---|---|
| **L1 저장소 분석** | 위 3장의 git·grep·HAPI 경로 비교, 자동 검사(`npm test`) | 부채 목록, 미사용 기능 후보, 변경 집중, 로직 | 없음 |
| **L2 합성 Hub + 헤드리스 Chrome** | `npm run ux`([tools/ux](../tools/ux/README.md)): 가짜 Hub(예시 세션·메시지, 실제 자료 없음)에 앱 서버를 붙이고 격리 프로필 Chrome으로 과업을 실행·캡처 | 화면 모양·상태별 표시, 클릭 흐름, 서버 경로 호출 횟수, CSP 오류 | 없음(격리 포트·임시 폴더) |
| **L3 격리 실제 인스턴스** | 개발 빌드를 별도 데이터 폴더·별도 포트(웹·Hub)로 실행. 실제 HAPI Hub/Runner + 시험용 엔진 실행 파일(스크립트 응답) | 재개·대기열·중지·`hapi resume` 터미널 넘기기 등 실제 HAPI 흐름 | 사용자 확인 권장: 터미널 창이 열리고 시험 프로세스가 뜬다. 실제 계정·대화 미사용 |
| **L3+ WebKit 화면** | Safari WebDriver(`safaridriver`)로 L2/L3 화면을 WebKit에서 조작·캡처 | Mac 앱(WKWebView)과 같은 엔진의 표시·입력 | 사용자 1회 설정: `safaridriver --enable`(관리자 암호)과 Safari ‘원격 자동화 허용’ |
| **L4 실제 AI·실제 데이터** | 격리 인스턴스에 사용자 CLI 계정을 연결해 실제 응답, 또는 실행 중인 개발 앱 화면 캡처 | 사고 과정 전달 여부, 실제 편집 카드, AI의 @경로 읽기, 실제 MCP | 사용자 승인 필수: 구독 사용량, 실제 대화·회사 자료 노출, 화면 기록 권한 |

L1·L2는 기능을 만들 때마다 기본으로 한다. L3 이상은 단계마다 사용자 확인 후 진행하고, 실제 자료는 출력하거나 커밋하지 않는다(AGENTS.md 경계).
