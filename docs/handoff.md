## 실제 엔진 기본 기능 검증 — 2026-11-02 (main, 미배포)

- 방법: 저장소 소스의 제품 백엔드(`runtime.mjs`)를 설치본의 Node26.12.1·HAPI0.33.3으로 실행하고, 격리 데이터 폴더(`.runtime/dev-test-data`)에 사용자가 직접 Claude·Codex 구독 로그인을 1회 했다. 시험 전용 Git 폴더(`.runtime/test-project`)만 사용했다. UI는 별도 프로필의 헤드리스 Chrome을 DevTools 프로토콜로 조작하고 화면을 캡처해 확인했다. 실제 사용자 앱·`~/.claude`·설정은 변경하지 않았다. Codex CLI0.166.0은 사용자 승인으로 brew 설치했다.
- **된다 — Claude:** 새 대화 생성→파일 읽기 도구 사용 응답, AI 제목 갱신. default에서 Write 승인 요청 표시→이번만 허용→실제 파일 생성. Bypass 적용 시 서버 보고값 `bypassPermissions`, 승인 없이 수정.
- **된다 — Codex:** 새 대화→명령 실행 응답. 기본 `read-only`에서 쓰기 시 승인 요청, 거절 처리. `yolo`(전체 접근) 적용 시 서버 보고값 일치, 승인 없이 파일 생성.
- **된다 — 가져오기 맥락 재개(처음 실증):** 격리 프로필로 Maricode 밖에서 만든 Claude CLI 대화를 별도 원본 폴더에서 가져오면 수동 클릭 없이 자동 재개되고, 원래 대화에서 알려준 단어를 정확히 답했다.
- **수정:** 가져오기 자동 재개(연결 대기), 승인 제목 `CodexBash`→`Codex Bash`, 세션 0개일 때 좌하단 "목록 상태를 확인해 주세요" 오표시, 새 대화의 프로젝트/프로젝트 없이 선택 상태 표시, 가져온 기록 안내문을 자동 재개에 맞게 수정.
- **간헐·미재현:** Claude 첫 승인 대기 중 방금 보낸 사용자 메시지가 잠시 보이지 않았다. 재시도에서는 재현되지 않았다.
- **된다 — 모드 유지:** Claude Bypass가 실행 종료→재개, 백엔드 전체 재시작→재개 후에도 서버 보고값 `bypassPermissions`로 유지된다. 다시 연 세션의 액세스 칩이 원시값 대신 프리셋 이름을 표시하도록 수정했다.
- **확인 안 함:** 네이티브 WKWebView 창에서의 동일 흐름(헤드리스 Chrome으로 대체), plan/acceptEdits/autoReview 실제 동작, 첨부·질문 UI, 서명 DMG 설치본.
- **수정 — 엔진 실패 표시:** 로그인이 없을 때 Claude가 응답 스트림 오류 후 같은 메시지를 조용히 재시도만 하고 화면에는 '접수 확인'만 남던 문제. 원인은 HAPI가 실패를 세션 이벤트(`type:'event'`, `Process exited unexpectedly…`, 3회 연속 시 메시지 폐기 안내)로만 보내는데 화면이 이 이벤트를 버리던 것이었다. `chat-presentation.mjs`에서 message/error 이벤트를 한국어 알림 줄로 표시하고 연속 중복은 합친다.
- **된다 — 실제 확인:** 격리 인스턴스에서 HAPI가 실행하는 Claude 바이너리를 잠시 '종료 코드1' 스크립트로 바꿔(키체인 로그인은 건드리지 않음) 실제 HAPI 런처 경로로 실패를 일으켰다. 채팅에 '엔진 실행 실패 — 다시 시도합니다…'와 '연속으로 실패해… 다시 보내 주세요'가 표시되고 '작업 중'이 풀렸다. 바이너리 복원 후 같은 세션에서 다시 보내 정상 응답을 받았다. Codex는 인증 파일을 잠시 치웠을 때 이미 401 오류를 Codex 메시지로 표시하고 있었다(복원 완료).
- **확인 안 함:** 실제 로그아웃 상태 Claude(키체인)에서의 문구, 네이티브 앱 창.

## 짧은 연결 코드 — 2026-11-03 (main, 미배포)

- 서버 Mac의 앱(로그인된 로컬 화면)에서 '⋯ → 다른 기기 연결 코드' 또는 ⌘K로 8자리 코드(XXXX-XXXX, 혼동 문자 제외)를 만든다. 코드는 메모리에만 있고 한 번에 하나, 5분, 1회용이며 5번 틀리면 폐기된다(`pairing.mjs`). 코드에는 토큰이 없고, 원격 로그인 화면의 '액세스 토큰 또는 연결 코드' 칸에 입력하면 서버가 확인한 뒤 자기 Hub 로그인으로 일반 세션 JWT를 발급한다(기존 로컬 연결 페이지와 같은 구조). 발급은 로컬 앱 + Hub 인증 확인, 사용은 기존 역할·출처·JSON 검사를 그대로 거친다. 사설망 접근 제약은 바뀌지 않는다.
- **된다 — 실제 확인(같은 Mac의 격리 인스턴스):** 코드 발급·남은 시간 표시 → 로그아웃 → 소문자로 입력해 로그인 성공 → 같은 코드 재사용 거부, 없는 코드의 거부 사유 표시. 자동 검사로 원격(전달 헤더) 발급 거부·다른 출처 사용 거부·만료·연속 실패 폐기를 확인했다.
- **확인 안 함:** 실제 다른 기기(사설망)에서의 입력, 네이티브 앱의 대화상자 표시. QR 이미지는 라이브러리 추가 결정 전까지 미구현. 인증 자동 갱신·기기별 취소는 사용자 결정으로 미룸.

## 명령 팔레트·대화 내 찾기 — 2026-11-03 (main, 미배포)

- ⌘K(Ctrl+K): 대화(제목·AI·프로젝트)와 기존 동작(새 대화, 가져오기, 찾기, 사이드바/상세 패널, AI 계정, 목록 새로고침), 단축키 목록을 검색·실행한다. 기존 버튼과 세션 선택만 호출하며 새 권한은 없다(`palette.mjs`).
- ⌘F: 대화 안 텍스트를 CSS Custom Highlight API로 표시하고 개수·현재 위치, Enter/Shift+Enter 이동, Esc 닫기. 버튼 글자는 제외하고 DOM은 바꾸지 않는다. 한글 조합 중 키는 처리하지 않는다.
- **된다 — 실제 확인(헤드리스 Chrome):** 'grape' 검색 → 대화 2건 → Enter로 열기, 'GRAPE' 찾기 9건 중 1/9→2/9 이동·강조.
- **확인 안 함:** 네이티브 앱(WKWebView)에서 ⌘K/⌘F가 메뉴 단축키에 가로채이지 않는지, Safari의 Highlight API 표시.
- 참고: 전체 자동 검사가 한 번 1건 실패했다가 재실행에서 315개 모두 통과했다(시간 의존 테스트로 보이며 원인 미확인).

## 다른 AI로 인계(배포 앱 활성화) — 2026-11-03 (main, 미배포)

- 기존 인계는 예전 시험용 고정 대상(`handoffTarget`)에만 연결돼 배포 앱(Runner 작업공간)에서는 꺼져 있었다. 배포 앱에서는 세션 정보의 '새 Codex/Claude 세션으로 인계 준비'가 일반 새 대화 생성 경로(같은 요청 ID 중복 방지·결과 확인 흐름)로 같은 프로젝트에 다른 AI 세션을 만들고, 최근 대화 일부(출처·대상·포함/생략 범위 표시)를 입력창에 넣기만 한다. 전송은 사용자가 검토 후 직접 한다. 원래 세션·파일·도구 결과·승인은 전달하지 않는다. 인계 본문 머리말의 '시험' 표기를 뺐다.
- **된다 — 실제 확인:** Codex 대화(텍스트 17개) → 새 Claude 세션 생성·이동, 입력창 초안 확인 후 전송, 이어서 물은 기억 단어를 Claude가 정답(GRAPE31).
- **확인 안 함:** 생성 결과 미확인 상태에서 결과 확인으로 이어 채우기, 긴 대화의 생략 표시, 출처 세션 연결 표시(시험판의 '출처 세션으로 이동'은 배포 앱에서 아직 미연결).

## 대화 분기(되감기 대체) — 2026-11-03 (main, 미배포)

- HAPI 0.33.3에서 제자리 되감기는 두 엔진 모두 미지원(`rewindToMessage:false`, Claude는 rewind 거부)이다. 대신 세션이 `forkAtMessage`를 알리는 Codex 대화에서 내 메시지 아래 '여기서 분기'(두 번 눌러 확인)를 누르면 그 메시지 직전까지의 대화로 새 세션을 만들고 연다(HAPI `/sessions/:id/fork`). 원래 대화는 그대로 두고 파일 변경은 되돌리지 않는다고 버튼·안내에 표시한다. Claude는 특정 메시지 분기를 지원하지 않아 표시하지 않는다.
- 함께 수정: 대화 화면 재그리기 생략 조건에 '분기 가능 여부'가 빠져 있어 세션이 실행 가능해져도 버튼이 나타나지 않던 문제.
- **된다 — 실제 확인:** Codex 대화(메시지 17개)의 두 번째 질문에서 분기 → 첫 주고받기만 있는 새 대화 생성·이동, 새 대화가 기억 단어는 알고 이후의 sleep 실행은 모른다고 답함, 원래 대화 유지.
- **확인 안 함:** 여러 메시지로 된 턴 중간에서 분기(HAPI가 거부해야 함), Claude 전체 복제(미노출).

## 턴 종료 알림 — 2026-11-03 (main, 미배포)

- 보고 있지 않은 대화(또는 창이 가려진 동안의 현재 대화)에서 작업 완료·승인/답변 대기·작업 중 실행 종료가 생기면 제목줄 아래에 '작업 완료 · 대화 제목'과 '열기'를 띄운다(30초 뒤 자동 닫힘, 최대 4개). 창이 가려져 있으면 창 제목에 '(개수)'를 붙이고 다시 보면 지운다. 대화 원문은 넣지 않으며 OS 알림은 쓰지 않는다(`turn-alerts.mjs`).
- 연속된 세션 상태 비교로 판단한다. 다른 대화가 작업 중이면 10초, 아니면 30초마다 확인하고, 현재 대화의 실시간 상태도 기록해 대화를 떠나는 순간의 '작업 중'을 놓치지 않는다.
- **된다 — 실제 확인:** Codex 대화에 15~20초 셸 작업을 맡기고 다른 대화로 옮긴 뒤 완료 알림 표시, '열기'로 해당 대화 이동.
- **확인 안 함:** 승인 대기·실행 종료 알림의 실제 발생, 창이 가려진 상태의 제목 표시(헤드리스로는 확인 불가), 네이티브 앱.

## 재개 실패 복구 — 2026-11-03 (main, 미배포)

- 문제: 재개 요청이 HAPI에서 실패하면 Runner가 '결과 미확인'에 머물렀고, 해제 조건이 '그 대화가 실행 중으로 확인됨'뿐이라 실제 실패는 영원히 풀리지 않았다. 모든 대화의 전송·재개, 앱 종료, 계정 전환이 막히고 화면은 '접수 여부 확인 중'에 멈췄다.
- 수정: 실패 후 15초가 지나고, 우리가 띄운 Runner가 살아 있고 허브에 연결돼 있으며, 허브가 그 대화를 실행 중이 아니라고 보고하면 '재개되지 않음'으로 확정해 해제한다(Runner 프로세스 자체가 종료됐으면 '종료'로 해제). 화면은 진행 중 요청이 없고 서버가 미확인을 보고하지 않으며 대화가 실행 중이 아니고 20초가 지나면 대기 표시를 풀고 '재개가 시작되지 않았습니다 … 다시 눌러 주세요'를 안내한다. 대기 중에는 30초마다 상태를 다시 읽는다. 어느 쪽도 재개를 자동으로 다시 보내지 않는다.
- **된다 — 실제 확인:** 시험 대화의 Codex 원래 기록을 잠시 치워 실제 재개 실패를 만든 뒤 손대지 않고 1분 안에 자동 해제·안내·재개 버튼 복귀를 확인했다. 기록 복원 후 같은 대화 재개·기억 단어 정답, 이후 앱 정상 종료까지 확인했다.
- **확인 안 함:** 백엔드를 강제 종료해 미확인 표시 파일이 남은 채 다시 시작한 경우(이번 수정 범위 밖, 여전히 '상태 확인 필요'로 남는다).

## 같은 AI 여러 계정(한 번에 한 계정) — 2026-11-03 (main, 미배포)

- 결정: HAPI는 대화가 Runner 환경을 그대로 물려받고 대화별 계정 지정 경로가 없다(spawn 토큰 옵션은 웹 경로 미공개·재개 시 미전달). 계정별 Runner(동시 실행) 대신 사용자 결정으로 'AI별 한 번에 한 계정' 방식을 구현했다.
- 구현(`account-profiles.mjs`): 기존 전용 프로필이 '기본 계정'이 되고, 이름을 붙여 계정을 추가하면 `profiles/<ai>-<id>` 전용 폴더를 만든다. 전환은 실행 중 대화·미확인 생성 요청이 없을 때만 허용하고, Runner를 먼저 정상 종료한 뒤 계정 환경의 `CLAUDE_CONFIG_DIR`/`CODEX_HOME` 한 값만 등록 잠금 아래 바꾸고 같은 기기 ID로 다시 준비·시작한다. 인증정보는 읽거나 복사하지 않으며 새 계정은 전환 후 기존 공식 로그인으로 연결한다. 추가·전환은 로컬 앱에서만 허용한다.
- 재개 보호: 별도 대화-계정 기록 없이, 재개 시 그 대화의 원래 기록이 어느 계정 프로필에 있는지 확인해 현재 계정이 아니면 '다른 계정(‘이름’)에서 만들었습니다'로 거부한다(Codex는 보관된 대화의 `archived_sessions`도 확인).

## 안 된다 / 확인 안 함

- **확인 범위 밖:** 모든 전이 의존성의 법률 감사, Bun/WebKit 전체 재컴파일, 비트 단위 빌드 재현. 이번에는 실제 배포 구성요소의 고지·소스 경로·빌드/교체 안내 누락을 점검했다. 미실행 재빌드를 통과한 것으로 표시하지 않는다.
- **실패한 이관 시험:** 새 Runner의 agent-availability가 HTTP500 `RPC handler not registered`를 반환해 AI 재개 요청을 전송하지 않았다. Runner 종료는 늦게 확인돼 앱의 정상 종료 보호가 남았다. 사용자 승인으로 새 시험 앱만 종료했고 이후 이관 자체를 중단했다. 원인은 확정하지 않았고 보조 환경 플래그/TMPDIR 보존 가설도 검증하지 않았다. 이 오류를 해결 완료로 쓰지 않는다. 출시용 깨끗한 환경에서 Runner 연결·종료/재개를 확인한다.
- **확인 안 함 — 실기:** 깨끗한 release 첫 실행/Applications 덮어쓰기·정식 데이터 보존, 두 번째 Mac, 별도 LAN HTTPS·장시간 절전 복귀, 실제 Codex 질문 UI·하위 에이전트 전체 수명주기.
- **미완료 후속:** 같은 AI의 다중 계정, 통합 MCP, 선택형 Git 자동화/여러 저장소 묶음, D5 로컬 기기 간 native 세션 이식, QR, 실제 보안 로그인 입력 연동. 초기 출시 범위를 계속 늘리지 않는다.
