## 지금 상태 — 2026-11-02

**MARICODE 1.0.0: D3 완료, D4 배포 준비 중. 새 저장소에서만 제품을 개발한다. 공개 출시 완료가 아니다.**

- 사용자 결정: 기존 시험 데이터/세션을 출시 환경으로 옮길 필요가 없다. 이관을 중단하고 새 저장소를 출시본의 독립 개발 기준으로 사용한다. 과거 이관·Runner 복구 절차를 다시 시작하지 않는다.
- 기존 로컬 mari-core와 이번 이관 때문에 만든 대용량 백업·복원·임시 데이터는 삭제했다. 원격 mari-core는 비공개 백업으로 최소 **2026-11-09까지** 유지한다. 자동 삭제 예약은 없으며 날짜가 됐다고 자동 삭제하지 않는다. 원격은 소스/Git 이력만 보존하고 Git 제외 시험 세션·프로필까지 보존하는 것은 아니다.
- 기존 원격 main의 최종 커밋 `105cac6`과 로컬 HEAD가 같음을 확인한 뒤 삭제했다. 약16MB의 비공개 Git bundle/원격 메타데이터 백업도 별도로 남겼다. Oracle 사본·Hermes·Paseo·일반 사용자 폴더는 정리 대상이 아니다.
- 최신 후보는 `.runtime/release-1.0.0-final46/MARICODE-1.0.0-arm64.dmg`이다. SHA-256: `896e5d1f803f41429e68c49c94e816a5cd143ebca0850620620389267ce5b250`. 빌드 앱은 `.runtime/release-build46/MARICODE.app`; 현재 실행 중인 이전 앱을 교체하지 않았다. 이전 후보는 되돌리기용으로 남겼으며 최신 후보와 혼동하지 않는다.
- GitHub MARICODE는 private, `v1.0.0` 릴리스는 draft다. 최신 후보 제품 기준은 `34d7aea88f7b518fc88d825986cbebeda404a7ec`. Runner 대기 수정·새 고지·수정 Bun 재빌드 안내·공식 로그인 창 수동 열기 안내를 포함한다. 원격 초안의 DMG·제품/Bun/WebKit 소스·체크섬·빌드/사용 안내·고지·라이선스9개와 SHA-256을 대조했다. Bun/WebKit 소스는 해시가 동일해 기존 첨부를 재사용했다. 초안 본문·대상 커밋도 갱신했고 아직 공개하지 않았다.
- 기존 배포용 Application Support/MARICODE 데이터(세션0개)는 이관 이전 상태로 복구했다. 이관용 사본을 계속 실행하지 않는다. 정식 제품의 사용자 데이터 보존 요구는 계속 유지하며, 과거 시험 데이터 폐기와 구분한다.
- 새 저장소의 핵심 실사용 시험을 마쳤다. Codex 구독 로그인·시험 프로젝트 등록·파일 읽기/한국어 응답·정상 종료·같은 세션 재개·도구 없이 이전 맥락 답변을 확인했다. 사용자는 전체 재시험을 원하지 않으므로 Claude/UI/원격 전체 시험으로 확대하지 않는다. 시험 세션은 재개 후 입력 대기 상태이며 대화와 파일은 유지한다.
- Codex 공식 로그인의 자동 터미널 열기는 실행 시작 전 멈췄고 사용자가 Finder의 기존 로그인 파일을 직접 열어 완료했다. 자동 열기의 원인은 미확정이다. 첫 Runner 준비 확인도 일시 실패했으나 같은 요청의 결과 확인 후 세션 생성은 한 번만 진행됐다. 시작 직후 식별 정보 조회 예외가 대기를 중단하는 코드를 수정했고 관련 테스트12개가 통과했다. 수정된 최종 번들의 격리 HAPI 연결/종료/재시작은 확인했다. 최종 DMG를 마운트해 설치 화면을 보는 검증은 아래 사유로 미확인이다.

- 배포 고지·대응 소스·빌드 안내의 제한된 누락 점검을 마쳤다. 기존10개 미해결 표기 중9개는 원본/보충 고지 또는 배포 패키지의 MIT 선언과 표준 약관으로 채웠고, Spline1개는 사용하지 않는 UI peer의 의존성으로 제외했다. 역사적 원문과 현재 upstream 보충본/표준 약관은 구분해 표기했다. intersection-observer는 패키지 메타데이터와 달리 소스 헤더가 지정한 W3C 고지를 추가했다. 실제 포함된 ripgrep14.1.1/PCRE2 10.43의 전체 고지도 보완했다.
- 앱의 제품/Node/HAPI/Paseo 고지·HAPI 소스 해시, 원격 draft의 Bun/WebKit 소스 해시를 대조했다. BUILDING에 수정 WebKit의 Bun 빌드→`--compile-executable-path`로 HAPI에 포함→앱 사본 교체/재서명 절차를 명시했다. 전체 upstream 재빌드는 실행하지 않았다. 고지 패키징 실제 확인과 관련 검사6개 통과. 최종 후보에 반영했고 초안 첨부도 갱신했다.

## 된다 — 확인한 범위

- 최종46 후보: 앱 빌드, DMG 생성·이미지 검증, 생성 과정의 앱 사본 ad-hoc deep/strict 서명 검증 통과. 포함된 Runner 코드/고지/안내가 저장소와 일치하고 DMG와 함께 생성한 제품 소스의 모든 파일이 빌드 앱의 포함 소스와 일치한다. 새 번들의 실제 HAPI 연결·정상 종료·재시작과 머신 ID/인증 보존을 격리 환경에서 확인했다. 실제 사용자 데이터나 기존 실행 앱은 교체하지 않았다.
- 독립 체크아웃의 자동 테스트237개, Node26.12.1/HAPI0.33.3 release 앱 빌드·ad-hoc deep/strict 서명 검증. 새 번들의 격리 Hub 인증·빈 세션 조회·workspace HTTP·정상 종료.
- 이번 새 소스 시험: 자동 테스트237개 재통과. 빈 데이터의 실제 HAPI0.33.3 Hub·Runner 연결/agent-availability·정상 종료를 확인했다. 공백 포함 데이터 경로에서도 통과했고, 같은 데이터/포트로 재시작한 뒤 연결·머신 ID·인증 정보 유지와 정상 종료까지 확인했다. 이 격리 서버 시험과 이후 출시 앱의 실제 Codex 대화 시험은 구분한다.
- 출시 앱의 브라우저 첫 실행 화면에서 로컬 역할 저장·페이지 재진입 후 복원·AI 미로그인 상태 표시를 확인했다. 브라우저 작업 화면에는 별도 HAPI 인증이 필요하며 네이티브 앱의 자동 연결 검증과 구분한다.
- 잠금 해제 후 네이티브 앱에서 토큰 수동 입력 없이 작업 화면에 연결됐다. 새 시험 폴더를 macOS 폴더 선택창으로 등록하자 프로젝트/기본 작업공간이 생기고 그 폴더·Codex가 선택된 새 세션 준비 화면으로 이어졌다. 기존 개인 프로젝트에서는 AI 작업을 실행하지 않았다.
- 이전 실제 시험의 역할·공식 계정 연결·Claude/Codex 응답/정상 종료·재개, Mac+Linux 다중 서버/Tailscale·단절 복구. 이전 데이터는 이번 정리로 폐기했으므로 시험 기록과 현재 사용 가능 데이터를 혼동하지 않는다.
- 이전 Mac 개발 앱의 계층 흐름·Claude 질문/이번 승인/거절·Finder 파일/이미지 붙여넣기·첨부 전송/제거·파일 선택·Dock 아이콘. 제품 코드는 유지된다.
- 릴리스 DMG의 이미지 검증·마운트/복사·서명·복사 번들의 실제 Hub 시작/인증/종료/재시작. 이관된 데이터에서 독립 앱의 native 창·자동 로컬 연결·대화 표시까지도 확인했으나 깨끗한 최초 설치 전체 시험과 구분한다.
- 정리 전 현재 대화를 실행하는 프로세스 계통과 Paseo/Hermes 제외를 확인했다. 사용자 승인된 새 이관 시험 앱3개와 기존 저장소의 시험 프로세스 트리51개를 종료했고, 확인한 동일 프로세스만 대상으로 했다. 실행 기록/데이터 초기화로 재개 실패를 숨기지 않았으며 이후 사용자의 시험 환경 폐기 지시에 따라 자료를 정리했다.
- 외장 볼륨 여유 약214→283GiB(약69GiB), 내장 약44→46GiB(약2GiB). APFS 복사본의 논리 용량 합계와 실제 회수 공간은 다르다.

## 안 된다 / 확인 안 함

- **안 된다:** 지금 초기 공개 배포 완료 선언. 저장소/릴리스는 아직 비공개/초안이다.
- **확인 범위 밖:** 모든 전이 의존성의 법률 감사, Bun/WebKit 전체 재컴파일, 비트 단위 빌드 재현. 이번에는 실제 배포 구성요소의 고지·소스 경로·빌드/교체 안내 누락을 점검했다. 미실행 재빌드를 통과한 것으로 표시하지 않는다.
- **실패한 이관 시험:** 새 Runner의 agent-availability가 HTTP500 `RPC handler not registered`를 반환해 AI 재개 요청을 전송하지 않았다. Runner 종료는 늦게 확인돼 앱의 정상 종료 보호가 남았다. 사용자 승인으로 새 시험 앱만 종료했고 이후 이관 자체를 중단했다. 원인은 확정하지 않았고 보조 환경 플래그/TMPDIR 보존 가설도 검증하지 않았다. 이 오류를 해결 완료로 쓰지 않는다. 출시용 깨끗한 환경에서 Runner 연결·종료/재개를 확인한다.
- **확인 안 함 — 최종 DMG 마운트:** 이미지 자체 검증은 통과했지만 이 Mac에서 hdiutil attach는 권한 거부, 권장 diskutil image attach는 응답 없이 대기했다. 이번에 시작한 정확한 diskutil 마운트 요청 프로세스만 종료했다. 세 번째로 Finder에서 최종 DMG를 직접 열었으나 설치 창이 나타나지 않았고 해당 이미지의 mount-point도 없었다. 세 방법이 모두 완료되지 않아 추가 시도를 중단했다. 다른 이미지/앱을 추출하거나 끄지 않았다. 새 이미지의 설치 화면을 봤다고 기록하지 않는다.
- **확인 안 함 — 실기:** 깨끗한 release 첫 실행/Applications 덮어쓰기·정식 데이터 보존, 두 번째 Mac, 별도 LAN HTTPS·장시간 절전 복귀, 실제 Codex 질문 UI·하위 에이전트 전체 수명주기.
- **미완료 후속:** 같은 AI의 다중 계정, 통합 MCP, 폴더 없는 대화, 선택형 Git 자동화/여러 저장소 묶음, D5 로컬 기기 간 native 세션 이식, QR, 실제 보안 로그인 입력 연동. 초기 출시 범위를 계속 늘리지 않는다.

## 다음 할 일

1. 최종 후보와 DMG 마운트 미확인 상태를 사용자에게 전달한다. 세 가지 마운트 방법이 완료되지 않았으므로 같은 환경에서 자동 재시도하지 않는다. 이미지 검증/새 번들 실행/소스 일치/업로드 확인은 완료했으므로 전체 기능 시험을 반복하지 않는다. 현재 실행 중인 이전 앱/AI 세션을 임의 종료하지 않는다.
2. 최종 후보와 공개 안내를 사용자에게 보여 준 뒤 저장소 공개·v1.0.0 발행을 진행한다. 지금은 비공개/초안으로 보존한다. 고지 조사를 다시 확대하지 않는다.
3. 2026-11-09 이후 이전 원격 저장소의 보존 종료를 검토한다. 현재 원격 삭제/공개 전환/릴리스 발행은 하지 않았다.
