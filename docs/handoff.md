## 가운데 파일 탭 뷰어 — 2026-11-04 (미배포)

- 사용자 요청: 오른쪽 파일 탐색기에서 연 파일을 가운데에 새 탭으로 보고, 개발 파일·영상·마크다운(보기 모드)을 바로 확인한다. 직접 구현보다 라이브러리 사용.
- 사용자 결정: markdown-it 15.0.3 + highlight.js 11.12.0을 `pilots/hapi/client-probe/vendor/`에 포함(라이선스 `vendor/LICENSES.txt`, NOTICES 반영). 이미지·영상·오디오·PDF는 WebKit 기본 표시. 큰 영상은 이 Mac 세션만 직접 스트리밍.
- 동작: 가운데 위 탭 줄(파일을 열 때만 보임)에 ‘대화’ + 파일 탭(최대 12개, 닫기). 세션을 바꾸면 파일 탭을 닫는다. 읽기 전용.
  - 텍스트/코드: 기존 HAPI 파일 읽기, 줄 번호, 512KB 이하만 색 구분(언어 파일은 필요할 때 불러옴). 8MB 초과는 읽지 않고, NUL 바이트가 있으면 미리보기 없음.
  - 마크다운: 보기 모드 기본, ‘원본’ 전환. 원시 HTML은 끄고(`html:false`) 문자로 표시. 외부 링크는 채팅과 같은 새 창 링크, 상대 링크는 폴더 안 파일 탭으로 열고 폴더 밖·기타 스킴은 링크를 없앤다. 상대 이미지는 미디어 링크로 표시, 외부 이미지는 CSP로 막힌다.
  - 미디어: `GET /api/sessions/:id/file-link?path=`가 기존 파일 읽기와 같은 세션·기기·폴더 검사 후 그 파일 하나에 대한 15분(사용 시 연장) 링크 `/file-raw/<토큰>`을 발급한다. 토큰 링크는 Range를 지원하고 Origin 헤더가 있으면 거절, 실제 경로가 바뀌면 끊는다. 허용 형식은 이미지·mp4/mov/webm·오디오·PDF뿐이고 SVG/HTML은 텍스트로만 보인다. PDF 외에는 `sandbox` CSP.
- 실사용 신고: 앱을 새로 켜면 Runner가 첫 전송/재개 전까지 꺼져 있어 파일 목록이 ‘컴퓨터 설정에서 실행 환경 시작’ 오류만 보였다(설정 화면에도 시작 버튼 없음, 이번 기능 이전부터 있던 문제). Runner가 꺼져 있으면 이 Mac 자신의 Runner 기기 ID(로컬 settings.json)와 세션 기기가 같고 등록 폴더가 일치할 때만 앱 서버가 디스크에서 직접 목록·파일을 읽는다(HAPI와 같은 응답 형식, 16MB 한도). Runner를 시작하지 않으며 다른 기기 세션은 그대로 막는다.
- 파일 탐색기(사용자 요청 ‘파일/폴더 구분이 안 됨’, 아이콘은 사용자 선택 Material Icon Theme 5.40.0 MIT): 오른쪽 목록을 VS Code식 트리로 바꿨다. 폴더는 그 자리에서 펼치고(▸/▾, 들여쓰기, 열린 폴더 아이콘), 파일은 형식별 색 아이콘, 열린 파일 강조. 심볼릭 링크(HAPI `other`)는 링크 폴더 아이콘이며 폴더로 먼저 열어 보고 아니면 파일 탭으로 연다. 새로고침은 아직 있는 열린 폴더를 유지한다. 상위 폴더 버튼은 트리 화면에서 숨겼다. 아이콘은 93개만 `vendor/file-icons/`에 포함(NOTICES·LICENSES 반영).
- **된다 — 자동:** 421개 통과(실제 HTTP Range·만료·형식 제한·링크 바꿔치기, 서버 경유 발급 401/403/415, markdown-it HTML/스크립트 링크 차단, 언어 파일 로드, 탭 동작). **확인 안 함:** 실제 앱 화면에서 탭·영상 재생/탐색·PDF iframe 표시·마크다운 링크/이미지, 좁은 화면.

## MCP 연결 실패(PATH)·/mcp 카드와 대화 상태 불일치 — 2026-11-04 (미배포)

- 실사용 보고: 슬랙·피그마 MCP가 대화에서 연결되지 않고 `/mcp` 카드 상태와 채팅 내용이 달랐다. 원인 두 가지를 확인했다.
- **PATH:** 앱이 CLI에 넘기는 PATH가 앱 Resources와 `/usr/bin:/bin:/usr/sbin:/sbin`뿐이라 `npx`로 띄우는 stdio MCP가 대화 시작 시 ENOENT로 실패했다. 셸 시작 파일을 실행하지 않고 터미널의 path_helper와 같은 `/etc/paths`·`/etc/paths.d`(Homebrew 등록)와 `~/.local/bin` 중 존재하는 폴더를 뒤에 덧붙인다. 새 설정과 기존 설치(앱 시작 시 `addCliUser`)에 모두 적용한다. 기존 순서는 유지해 앱 Node가 먼저 잡힌다.
- **카드 불일치:** 카드는 매번 새 CLI 조회라 설정 수정 후 ‘연결 확인’으로 보이지만, 실행 중 대화는 시작 시 연결 상태를 유지한다. 또 ‘이 대화의 MCP’는 시작 도구 목록만 써서 Claude가 나중에 불러오는(deferred) MCP를 빠뜨렸다. 이제 대화 기록의 도구 호출·ToolSearch 결과로 불러온 MCP를 더하고, Claude가 보고한 ‘연결 실패’ 서버를 따로 표시하며 ‘같은 세션 다시 시작해 MCP 다시 불러오기’ 버튼(기존 재개 절차)을 둔다.

## CLI 환경 유지·자체 채팅 연결 검토 — 2026-11-03

## 부분 구현 정리 — 2026-11-03 (1.0.11 포함)

- **계정 이름 변경·삭제:** 계정 카드에서 선택한 계정의 이름을 바꾸고, 사용 중·기본 계정이 아니면 두 번 눌러 목록에서 삭제한다. 삭제는 숨김 표시이며 로그인 폴더는 남긴다. 그 계정으로 만든 대화는 '목록에서 삭제한 계정(‘이름’)에서 만들었습니다'로 재개를 계속 거부한다(완전히 지우면 재개 보호가 그 대화를 알아보지 못해 현재 계정으로 재개되기 때문).

- 함께 수정: 새 대화 패널이 '가져오기' 상태로 남아 있으면 인계 버튼이 아무 반응 없이 무시되던 문제.
- **된다 — 실제 확인:** 이름 변경→삭제(폴더 유지)→삭제한 계정 대화 재개 거부 문구, 인계 후 출처 표시·이동. 하위 폴더 목록은 자동 검사로만 확인(실제 하위 폴더 스레드 재개는 확인 안 함).

## 대화 분기(되감기 대체) — 2026-11-03 (1.0.11 포함)

- HAPI 0.33.3에서 제자리 되감기는 두 엔진 모두 미지원(`rewindToMessage:false`, Claude는 rewind 거부)이다. 대신 세션이 `forkAtMessage`를 알리는 Codex 대화에서 내 메시지 아래 '여기서 분기'(두 번 눌러 확인)를 누르면 그 메시지 직전까지의 대화로 새 세션을 만들고 연다(HAPI `/sessions/:id/fork`). 원래 대화는 그대로 두고 파일 변경은 되돌리지 않는다고 버튼·안내에 표시한다. Claude는 특정 메시지 분기를 지원하지 않아 표시하지 않는다.
- 함께 수정: 대화 화면 재그리기 생략 조건에 '분기 가능 여부'가 빠져 있어 세션이 실행 가능해져도 버튼이 나타나지 않던 문제.
- **된다 — 실제 확인:** Codex 대화(메시지 17개)의 두 번째 질문에서 분기 → 첫 주고받기만 있는 새 대화 생성·이동, 새 대화가 기억 단어는 알고 이후의 sleep 실행은 모른다고 답함, 원래 대화 유지.
- **확인 안 함:** 여러 메시지로 된 턴 중간에서 분기(HAPI가 거부해야 함), Claude 전체 복제(미노출).

## AI 세부 옵션 — 2026-11-02 (1.0.11 포함)

## 안 된다 / 확인 안 함

- **확인 범위 밖:** 모든 전이 의존성의 법률 감사, Bun/WebKit 전체 재컴파일, 비트 단위 빌드 재현. 이번에는 실제 배포 구성요소의 고지·소스 경로·빌드/교체 안내 누락을 점검했다. 미실행 재빌드를 통과한 것으로 표시하지 않는다.
