# Maricode — 제품 목표와 요구사항

제품 이름은 **Maricode**, 초기 배포 버전은 **1.0.0**이다. 표시 이름은 Maricode로 통일하고, 제목 영역에 현재 버전을 함께 표시한다. Dock 아이콘 이름도 Maricode로 표시되도록 앱 번들 파일명은 `Maricode.app`으로 맞춘다. 업데이트 호환성을 위해 기존 앱 식별자·저장 경로·DMG 배포 파일명은 유지한다. 아래는 요구사항이며 실제 구현/검증 상태는 `handoff.md`를 따른다. 미구현 요구를 출시 기능으로 표시하지 않는다.

## 범위와 구조

독립 개발툴로 Claude Code와 Codex의 채팅·작업 흐름·파일·승인·세션 재개를 제공한다. 자체 개인비서, 상시 알림/예약 실행, 통합 모니터링은 별도 제품 범위다.

Mac 앱은 Swift/AppKit + WKWebView 안에서 공통 웹 UI를 제공한다. 연결은 REST/SSE → HAPI Hub/Runner → AI 실행 엔진이다. HAPI 공개 기능을 우선 활용하고 필요한 보완만 작게 한다. 기존 외부 도구에 플러그인을 설치하거나 다른 앱의 운영 서버를 교체하지 않는다.

Claude/Codex 구독 로그인을 우선하며 API 키 과금만 되는 경로를 강제하지 않는다. 서버 접속 인증과 AI 계정 인증은 별개다. 실패 시 다른 AI·계정·유료 API로 자동 대체하지 않는다.

2026-11-03 CLI 위임 원칙: 기본 목표는 사용자가 터미널에서 쓰는 공식 CLI의 실행 파일·작업 폴더·계정·설정 저장소·필요한 환경을 그대로 사용하고 Maricode가 채팅/승인/파일 화면을 제공하는 것이다. MCP 설정·인증을 별도 사본으로 관리하지 않는다. 후속 사용자 결정으로 앱 전용 프로필 생성·계정 추가·여러 프로필 전환은 제거한다. AI별로 설치된 공식 CLI와 설정 위치 하나만 연결한다. 별도 계정/격리 프로필은 필요가 생기면 재검토할 낮은 우선순위 후보이며 현재 구현 범위에서 제외한다. 로그인·MCP·설정은 연결한 CLI 저장소를 직접 사용하고 복제하지 않는다. CLI 기본 위치에서는 프로필 환경변수를 생략한다. Claude의 HOME/.claude.json과 CLAUDE_CONFIG_DIR/.claude.json은 서로 다른 설정 원본이므로 경로만 같게 지정해 동등하다고 가정하지 않는다.

동일 환경은 cwd만 같다는 뜻이 아니다. CLI 버전/실행 경로, HOME·CLAUDE_CONFIG_DIR·CODEX_HOME, PATH 및 MCP가 요구하는 환경, shell alias/wrapper/추가 인자, 설정 계층과 관리 정책, system prompt/권한 덮어쓰기를 함께 확인한다. 환경·비밀은 실행 머신 안에 유지하며 임의의 셸 설정 실행·환경변수 일괄 복사로 동등성을 가정하지 않는다. CLI의 workspace trust/프로젝트 MCP 승인이 비대화형 경로에서 생략되는 경우 앱이 명시적인 연결 동의 경계를 제공해야 하며 Bypass를 기본값으로 만들지 않는다.

채팅은 공식 CLI의 장기 실행/구조화 이벤트 경로에 연결한다. Claude는 공식 Agent SDK의 CLI 실행 경로, Codex는 App Server를 우선 검토한다. 실행 중인 세션의 MCP 상태/기능 목록과 원래 세션 ID를 사용하고, 설정 파일이나 별도 `mcp list` 출력을 현재 실행 상태의 대체물로 삼지 않는다. 터미널 전용 화면/명령의 완전한 자동 변환은 보장하지 않는다. 미지원 동작은 숨기거나 명시적 공식 CLI 보조 경로로 연결하며 일반 모델 프롬프트로 보내 성공으로 처리하지 않는다. HAPI 유지·보완·연결부 교체는 동일 환경 비교 시험 후 결정하고 이번 검토만으로 교체하지 않는다.

## CLI 직접 실행과 HAPI 채팅의 구분

| 경로 | 실제 실행·화면 | 공유하는 것 | 보장하지 않는 것 |
|---|---|---|---|
| 사용자가 연 공식 CLI | 터미널 → Claude/Codex TUI | 사용자의 셸·프로필·프로젝트 설정 | 앱 채팅과 동일 프로세스/화면 자동 동기화 |
| 터미널에서 이 세션 이어가기 | 앱 HAPI `resume <세션>` → Mac 터미널의 공식 CLI 화면 | Runner와 같은 환경·Hub·기기 ID, 같은 HAPI 세션(대화 기록 공유) | 원격 기기에서 열기, 셸 시작 파일/별칭 실행, Claude 앱·터미널 동시 입력 |
| 앱 채팅 | Maricode REST/SSE → HAPI Hub/Runner → 공식 CLI | 연결한 CLI 설정 폴더·계정·프로젝트 설정·원래 세션 ID | HAPI의 추가 지시문·MCP bridge·권한 변환 제거, 터미널 옵션 완전 동일 |

2026-11-04 사용자 결정: 채팅에서 모든 CLI 반응을 흉내 내기 어려워 명령 카드(/mcp·/plugins·/account·/doctor)와 별도 ‘공식 CLI 열기’를 제거하고, 채팅으로 못 보내는 명령은 HAPI의 같은 세션 터미널 이어가기(`hapi resume`)로 처리한다. Claude는 앱↔터미널로 조작권이 오가고 Codex(공유 app-server)는 동시에 쓴다. 아래 명령 카드 결정은 이력으로만 남긴다.
(이전 결정) 명령 카드는 설정 원본을 따로 소유하지 않고 공식 CLI에 인자를 전달한다. 설정 저장/인증 완료와 실행 중 채팅의 반영 완료를 구분한다. 설정을 바꾸면 정상 종료 후 같은 세션을 재개하고 실제 도구 연결을 확인한다. 공식 로그인은 CLI 인증 경로를 사용하며 HAPI 토큰은 서버 연결용으로 별개다. CLI 프로필 연결은 셸 환경변수·별칭·wrapper까지 가져오는 기능이 아니다. PATH와 추가 환경변수에 의존하는 MCP는 별도 검증이 필요하다.

## 이번 전환 버전의 일회성 초기화

**1.1.0 후속 결정:** 사용자가 이전 버전을 완전히 정리하고 새로 설치하는 전환 버전을 요청했다. 1.0.14의 부분 정리보다 이 결정을 우선한다. DMG 자체는 설치 스크립트를 실행하지 않으므로 Applications의 기존 앱 번들은 정상 종료 후 교체하고,1.1.0 첫 실행에서 앱 소유 데이터의 세션/대화·프로젝트 등록·역할·연결·Hub/Runner 자료를 한 번 삭제한 뒤 최초 설정 화면을 연다. 앱 내 WebKit 로그인/화면 저장 자료도 한 번 비운다. 외부 작업 소스·CLI 설정/원본 기록·다른 브라우저·원격 서버는 정리하지 않는다. 실행 소유 잠금과 공식 로그인/CLI 진행 상태를 확인하고 중단된 정리도 동일 기록으로 이어 처리한다. 완료 표식 이후 재실행/재설치에는 새 데이터를 보존한다. 단순 DMG 다운로드/마운트만으로 초기화하지 않는다. 아래 부분 정리와 수동 초기화 결정은1.0.14 당시 기록이다.

2026-11-03 사용자는 현재 단독 시험 사용자이며 보존할 진행 작업이 없다고 확인했고, 다음 전환 업데이트에 한해 기존 앱 전용 프로필을 삭제하고 다시 설정하도록 승인했다. 일반 업데이트 정책을 영구 초기화로 바꾸는 것이 아니다.

- 앱 실행 잠금을 확보한 뒤 Hub/Runner 시작 전에 앱 소유 `local-setup/profiles`와 연결 등록 정보를 정리한다. 공식 로그인 미완료·외부 경로·심볼릭 링크 경계는 임의로 넘지 않는다.
- 기존 CLI의 `.claude-global`·`.claude`·`.codex`, 프로젝트 파일, Hub의 화면 이력은 삭제 대상이 아니다. 전용 프로필에만 있던 원본 세션은 삭제되므로 남은 화면 이력을 이어갈 수 있다고 표시하지 않는다. 이관용 복사본·백업을 새로 만들지 않는다.
- 전환 완료 표식을 저장하고 이후 실행/업데이트에서는 반복하지 않는다. 기존 CLI 연결 확인을 다시 받고, 연결 전 로그인/채팅 실행을 시작하지 않는다. 신규 설치는 앱 전용 프로필을 만들지 않는다.
- 2026-11-03 회사 Mac 전환 재확인에서 사용자가 완전 초기화 후 재설치도 허용했다. 이는 해당 기기의 Maricode 앱 데이터 수동 초기화 선택이며, 외부 CLI 설정/원본 세션·작업 소스·다른 기기는 제외한다. 일반 업데이트 때 전체 앱 데이터를 자동 삭제하는 정책으로 확대하지 않는다.

## 컴퓨터 역할과 데이터 경계

2026-11-06 사용자 결정(원격 분리): Mac 앱은 이 Mac에서 작업하는 앱이다. 다른 컴퓨터에 접속하는 일은 그 서버의 웹 화면을 브라우저·PWA로 연다. Mac 앱의 컴퓨터 탭·컴퓨터 연결 화면·서버 검색과 ‘원격’ 역할은 없앤다.

- **로컬(기본):** 처음 설정은 로컬 모드만 준비한다. 파일·세션·실행 상태가 이 Mac에 남고, 외부 클라이언트에 직접 공개하지 않는다. 다른 로컬 기기로 이어가기는 별도의 명시적 세션 이식 기능이다.
- **다른 기기에서 접속 허용(선택, 서버):** 켜면 허용된 사설망(Tailscale) 클라이언트가 브라우저·PWA로 이 Mac의 같은 작업을 이어간다. 파일·AI 실행·연산은 이 Mac에 남는다. 서버 주소·HTTPS 전달·연결 코드·QR·로그인 유지 기기 관리를 한 곳에서 진행한다.
- 2026-11-07 사용자 요청: 앱 시작 시 다른 기기 접속 허용이 켜져 있고 주소 설정 파일이 없으면, 설치된 Tailscale의 실행 상태와 이 Mac의 DNS 이름을 조회해 HTTPS 주소를 자동 등록한다. 기존 주소·포트와 명시적 등록 해제는 보존한다. 조회 실패는 로컬 시작을 막지 않는다. 앱 시작 자체에서는 HTTPS 전달을 시작하지 않는다.
- 2026-11-07 후속 요청: Mac 앱에서 ‘다른 기기 연결’을 열면 주소가 없을 때 자동 등록을 시도하고, 이 앱의 HTTPS 전달을 준비한 뒤 새 일회용 코드를 발급해 QR을 바로 보여 준다. 이미 실행 중인 앱 소유 전달은 재사용한다. 기존 Serve 설정은 보존하며 미설치·HTTPS 승인 필요·불확실한 시작 결과는 안내하고 자동 재전송하지 않는다. 요청별 준비 완료를 구분하고 창을 닫은 요청의 QR은 띄우지 않는다.
- **원격 접속:** 브라우저·PWA가 담당한다. 여러 서버를 동시에 쓰면 서버마다 별도 창(설치 앱)이며, 서버별 인증·입력·미확인 요청·재연결은 각 창이 따로 가진다. 연결 단절 시 로컬로 대신 실행하지 않는다.
- 이전 버전의 원격 전용 Mac은 새 버전에서 처음 설정(로컬)부터 다시 시작한다. 저장해 둔 컴퓨터 탭 목록(`machine-tabs.json`)은 새 버전 첫 실행 때 지운다.
- 같은 망은 LAN·사내망·Tailscale을 포함한다. 공개 인터넷 릴레이/Funnel은 초기 범위 밖이다. 검색 결과 자체가 접속 권한은 아니다.
- 역할 선택은 회사/개인 자료의 소유·접근 정책을 바꾸지 않는다. 회사 자료를 개인 서버로 중계하지 않는다.

## 프로젝트·작업공간·세션

| 단위 | 책임 |
|---|---|
| 프로젝트 | 이름과 기준 폴더. 단일 Git 또는 여러 독립 저장소의 상위 폴더 |
| 작업공간 | 정확한 실행 폴더/체크아웃/worktree. 별도의 안정 ID |
| 세션 | 작업공간에 속한 AI 대화·계정 연결·모델 옵션·실행 상태 |

- 내부 계층은 컴퓨터 → 프로젝트 → 작업공간 → 세션이다. 왼쪽 목록에서는 기본 작업공간만 하나 있으면 중간 행을 숨겨 프로젝트 → 세션으로 표시한다. 작업공간이 여러 개거나 머신/폴더 구분이 필요하면 계층을 유지한다. 검색/보기 필터로 하나만 남았다는 이유로 계층을 합치지 않는다. 프로젝트 등록 시 기본 작업공간을 준비한다. 작업공간과 worktree는 동의어가 아니다.
- 최초 실행은 역할 선택 없이 로컬로 빈 레이아웃을 연다. 프로젝트·AI 계정을 모두 연결하도록 강제하지 않는다.
- 중앙 ‘대화 추가’에서 새 대화/기존 대화 가져오기를 먼저 선택한다. 프로젝트 선택/추가 → 필요한 작업 폴더·선택 Git 옵션 → AI/계정 → 대화로 이어진다. 기본 작업공간 하나면 선택칸을 생략한다. 새 대화 대상은 현재 대화와 분리해 목록 갱신에 흔들리지 않게 한다.
- ＋는 대화 추가를 뜻한다. 기본 공간 하나면 프로젝트 행에, 여러 공간이면 각 작업공간 행에만 두며 중복 ＋를 표시하지 않는다. 프로젝트 등록과 선택적인 워크트리 생성은 별도 동작이다.
- 대화는 사용자 지정 이름·실제 AI 제목·첫 입력으로 식별하고, 제목 정보가 없으면 짧은 ID로 구분한다. AI 종류와 실행 상태는 부가 정보로 표시한다. 가져온 이전 이력과 현재 앱의 이력 수를 구분한다.
- 기존 대화의 파일 목록 조회·CLI 설정 연결·구독 로그인·실행기 서버 연결·실제 AI 응답을 별도 상태로 표시한다. 목록이 보이거나 로그인 조회가 성공했다는 이유로 실행 준비 완료를 주장하지 않는다. 가져오기 전 실패와 접수 이후 미확인을 구분하고, 접수된 요청의 결과 확인은 CLI 재시작이나 등록 반복 없이 진행한다.
- 새 세션의 기본 AI는 같은 서버·정확히 같은 작업공간의 최근 세션에서 가져온다. 모델·추론 값도 조회해 새 세션의 지원 목록에 있는 값만 기존 설정 API로 적용한다. 사용자의 AI 선택은 우선하며 계정·승인·접근 권한을 자동 복제하지 않는다. 생성/설정 미확인은 자동 재전송하지 않는다.
- 같은 작업공간의 세션은 폴더와 브랜치를 공유한다. 독립 파일 변경에는 별도 worktree를 선택한다. 세션 종료가 폴더·브랜치·대화 삭제는 아니다.
- Git 없는 폴더와 현재 폴더 그대로 작업하기를 지원한다. 새 worktree는 선택 커밋에서 만들고 미커밋 파일을 자동 복사하지 않는다.
- 브랜치 변경은 미커밋 변경·다른 worktree 점유·활성 작업을 보호한다. Git 준비/세션 생성을 같은 요청에 결속하고 일부 성공·응답 유실을 자동 반복하지 않는다.
- 프로젝트 등록은 임의 경로 실행 권한이 아니다. 등록 ID로 실행 폴더를 확인한다. Runner 변경은 활성/미확인 세션을 보호하고 기존 대화/머신 ID를 보존한다.
- 프로젝트/작업공간/세션 표시 이름 변경과 등록 해제/숨김·복원을 제공하되 실제 파일·Git·대화를 지우지 않는다. 활성/승인 대기·미확인 작업의 제거를 차단한다.

## 세션 연속성과 실행 안전성

정상 종료 후 Claude/Codex 원래 세션으로 재개하는 것과, 다른 AI에 최근 텍스트를 전달해 새 세션을 만드는 것은 구분한다. 새 인계 세션에는 출처·전달 범위를 표시한다. 긴 대화 전체가 전달됐다고 보장하지 않는다.

같은 컴퓨터에서 MARICODE 밖의 Claude Code로 진행하던 기존 대화를 찾고 가져오는 것도 요구사항이다. MARICODE에서 만든 세션의 재개만으로 이 요구를 충족했다고 보지 않으며, 다른 컴퓨터 간 이식인 D5와 구분한다. 먼저 로컬 Claude를 지원한다. CLI에서 폴더로 이동한 뒤 대화를 고르는 것처럼 작업공간 선택 → 기존 세션 목록으로 이어져야 한다. 패널을 열면 해당 폴더의 기록을 자동 검색한다. 기록 저장 위치는 명시 선택, CLI 환경변수, 셸 설정의 단일 정적 경로, 기본 프로필 순으로 확인하며 사용한 위치와 출처를 표시한다. 셸 스크립트·별칭·함수는 실행하지 않고 동적/복수 후보는 직접 선택하도록 안내한다. Mac 앱에서는 숨김 폴더가 보이는 폴더 선택창을 제공하고 선택 후 자동 검색한다. 경로 직접 입력은 보조 수단으로 두며 ~/ 경로도 지원한다. 프로필 없음·해당 폴더 기록 없음·형식 제외를 구분하고 검색 위치를 확인할 수 있어야 한다. 등록한 작업공간과 원래 실행 폴더가 일치하는 기록을 기본 `~/.claude` 또는 사용자가 지정한 `CLAUDE_CONFIG_DIR`에서 찾고, 제목/첫 입력 일부·수정 시각으로 선택한다. 연결한 CLI와 같은 설정 폴더의 기록은 복사하지 않고 같은 native 세션 ID로 등록·재개한다. 터미널과 앱이 같은 대화를 동시에 실행하지 않도록 안내한다. 다른 기록 폴더를 명시적으로 선택한 경우에만 선택 기록을 현재 CLI 폴더로 복사하며, 두 사본을 자동 동기화하지 않는다. 작업 브랜치/워크트리는 가져오기만으로 변경하지 않는다.

가져오기는 로컬 앱/실행 컴퓨터의 loopback 화면에서만 허용한다. 회사 기록을 외부 서버로 탐색·전송하지 않는다. 계정·설정·MCP·메모리·첨부 파일을 묵시적으로 복사하지 않고 MARICODE에 명시적으로 연결한 계정을 사용한다. 필요한 환경/파일은 별도 확인한다. 원본 변경·잘못된 cwd·심볼릭 링크·기존 대상 기록을 보호하고 등록 미확인은 재전송하지 않는다. 이전 기록은 가져온 시점의 읽기 전용 텍스트로 구분하며 과거 도구 요청을 새 승인으로 재현하지 않는다. 원래 엔진의 맥락 재개와 화면의 이력 조회는 따로 검증한다. Codex 외부 기록도 같은 가져오기 화면에서 AI를 Codex로 골라 가져온다. 원래 Codex 기록 폴더(기본 `~/.codex`)에서 해당 프로젝트 폴더에서 시작한 최상위 스레드만 보여주고, 연결한 CLI 폴더의 rollout은 복사 없이 같은 스레드 ID로 연결한다. 다른 기록 폴더를 명시 선택한 경우에만 선택 rollout을 현재 CLI 폴더로 복사한다. 인증·설정·MCP·상태 DB는 복사하지 않는다. 이전 대화는 재개 시 엔진이 다시 채우는 기록으로 표시하며 중복 표시하지 않는다.

새 세션 만들기와 기존 세션 가져오기는 처음부터 별도 진입으로 구분한다. 가져오기 화면에 새 세션 생성 버튼을 함께 두지 않는다. 등록과 이전 기록 조회가 확인된 뒤 가져온 대화를 열며, 실패/미확인은 해당 화면에서 설명한다. 등록 후 화면 열기 실패는 동일 ID로 다시 열고 복사·등록을 반복하지 않는다. 복사 방식 안내는 표시하되 버튼을 막는 확인 체크박스를 요구하지 않는다. 가져올 대화 콤보박스 옆 새로고침 아이콘과 마지막 확인 시각을 제공한다.

같은 native 세션이 프로젝트 루트에서 시작해 하위 폴더에서 이어진 정상 이력은 가져올 수 있어야 한다. 다른 프로젝트·세션 ID의 기록은 자동 혼합하지 않는다. 실패 시 경로·대화 원문 없이 행 번호와 원인 종류를 구분하고, 통과시키기 위해 원본 행을 삭제하거나 cwd/ID를 덮어쓰지 않는다.

가져오기 직후 이전 대화를 자동으로 펼쳐 최근 내용부터 보여준다. 새 메시지와 하나의 스크롤 영역을 사용하며 오래된 기록은 추가로 조회한다. 사용자는 대화 내용을 보고 올바른 세션을 가져왔는지 확인할 수 있어야 한다. 이 표시만으로 엔진의 맥락 재개 성공을 선언하지 않는다. 등록이 끝나고 연결·대상 세션 상태가 재개 가능하면 수동 클릭 없이 바로 실행 재개까지 이어간다. 연결이 안 됐거나 이미 실행 중이거나 자동 재개가 실패하면 기존처럼 수동 재개 버튼으로 안내한다.

엔진 실행 실패·재시도·대기 메시지 폐기는 채팅에 원인과 함께 표시한다. '접수 확인'만 남기고 조용히 재시도하게 두지 않는다. 폐기된 메시지는 자동 재전송하지 않고 원인 해결 후 다시 보내도록 안내한다.

재연결은 이력·선택을 복구하되 접수 불명 요청을 재전송하지 않는다. 실행 중·승인 대기·생성/재개 미확인 상태에서 종료/업데이트/Runner 변경을 보호한다. 살아 있는 소유 불명 프로세스를 자동 인수·종료하지 않는다. 제한된 잠금 복구도 프로세스 종료와 기록 경계를 확인한 경우만 한다.

내부 심볼릭 링크를 탐색하되 프로젝트 밖 링크 접근은 별도로 허용된 범위가 필요하다. 경로·권한 실패를 숨기거나 다른 폴더로 대신 실행하지 않는다.

## 선택형 Git 자동화·여러 저장소 — 보류(아이디어)

## 로컬 기기 간 이어가기 — D5 요구
